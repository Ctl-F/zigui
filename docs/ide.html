IDE pieces

The workbench is growing into an IDE. Code that is specific to being one lives in src/ide/ (exported as zigui.ide); it builds on the framework (widgets, the editor, process plumbing), and the framework never imports it. The plan and the order of work are in NOTES/ide-plan.md.

Output panel

zigui.ide.OutputPanel runs a command and shows what it prints: stdout and stderr interleaved as they arrive, in a read-only editor that follows the end, with a status line (Running, Finished / Failed with the exit code and time, Stopped), a Stop button, and Clear. The first line shown is the command ($ zig build run) and the last is the result ([Finished: ... (exit 0, 1.2 s)]), so a command that prints nothing still shows that it ran. Lines that are compiler diagnostics are tinted by severity (error, warning, note) and double-clicking one calls your hook so you can open the file at that spot.

const out = try zigui.ide.OutputPanel.create(&ui, parent, .{
    .style = .{ .grow = 1 },
    .on_open = zigui.ide.output_panel.OpenHook.bind(&app, App.openAt),   // fn (*App, path, line, col) void
});
defer out.destroy();

try out.run(io, &.{ "zig", "build" }, project_dir, sdl.wake);   // replaces a run in progress

// every loop iteration (the worker threads wake the loop when output arrives)
out.poll();

The workbench docks one at the bottom; F5 (or Build → Build) runs zig build and Ctrl+Shift+T runs zig build test in the current directory.

Compiler output parsing

zigui.ide.buildout: parseLine(line) reads path:line:col: error|warning|note: message (Zig's format; Windows drive paths work) into a Diagnostic and returns null for anything else; stripAnsi removes color and cursor escape sequences. No UI.

Projects

zigui.ide.Project wraps a root directory (UI-free). Project.open(gpa, io, path), listDir(gpa, rel) (directories first, sorted ignoring case, skipping .git, .zig-cache, zig-out, node_modules and similar; free with freeEntries), readFile, writeFile, hasBuildZig, and absPath/relPath converters. Project paths are relative to the root with / separators.

Find in project

zigui.ide.search_project.Searcher.start(gpa, &project, query, options, wake) walks the project on a worker thread and streams Event.hit{path, line, col, text} followed by one Event.done{files, hits, truncated, cancelled}. Call drain from the UI thread, deinit each event, cancel to stop, destroy to join and free. It skips excluded folders, binary files (a NUL in the first 8 KiB) and files over 4 MiB, stops at 5000 hits, and uses the same matcher (case, whole word) as the editor's find bar.

Files, search and documents

Three panels build on the services above. Each is created into a dock panel's content node, has destroy(), and (where noted) a poll() to call every loop iteration.

TypeWhat it does
ide.FilesPanel.create(ui, parent, &project, .{ .on_open })A TreeView of the project. Folders read from disk when first expanded; activating a file calls on_open(path) with its project-relative path. reload() re-reads the root; selectedPath().
ide.SearchPanel.create(ui, parent, &project, .{ .on_open, .wake })Query field, Aa and whole-word toggles, a Search button, and results grouped by file (line:col text). setQuery, setOptions, start, cancel, running, and poll() to add arriving results. on_open(path, line, col) is the same hook type as the Output panel's.
ide.Documents.create(ui, dock, &project, io, .{ .anchor })Opens files as dock panels, each a CodeEditor (language from the extension, folding on) with a FindBar. open(path, line, col) reuses an open file, save, saveActive, saveAll, anyDirty, statusText. poll() puts a bullet in the tab of a modified file and removes closed ones. Closing a modified file is refused once (the status text says so); closing again discards. Files over 16 MiB open read-only (memory-mapped). New documents tab beside the anchor panel, then beside the last document.

Terminal

zigui.ide.TerminalPanel.create(&ui, parent, .{ .cwd, .environ, .wake, .argv }) is the integrated terminal: a Terminal widget wired to a shell on a pty. The shell ($SHELL) starts in the project folder once the widget has a size and follows it from then on. poll() every loop iteration; runCommand(text) types a command and presses Enter; focus(). When the shell exits the panel says so and the next key starts another. In the IDE app it is a tab beside Output; Ctrl+` shows and focuses it.

Restarting the IDE (building the IDE in the IDE)

zigui.ide.relaunch starts a fresh copy of the running executable so you can run the build you just made: argv(a, exe, project_root, open_files) builds the command line (the folder, then --open FILE for each file to reopen), spawnDetached(io, argv) starts it with no pipes so it outlives this process, openFilesFrom(a, args) reads the --open arguments back, and cleanPath drops the " (deleted)" the OS appends to the path of an executable that a rebuild replaced, so the new file is started. resolveExe(a, io, running) handles the other common case: a program started with zig build ide runs from the build cache (.zig-cache/o/<hash>/ide), and a rebuild installs the new build to zig-out/bin/ide while the cached copy stays old, so it prefers the installed file beside that build root when it exists.

In the IDE app (Ctrl+Alt+F-keys are taken by Linux for switching consoles, hence Ctrl+Shift): Ctrl+Shift+F6 saves every modified file, starts a new instance on the same folder with the same files open, and quits this one. Ctrl+Shift+F5 runs zig build first and restarts only if it succeeds (otherwise the status line says the build failed and nothing happens). In headless script runs (ZIGUI_SCREENSHOT set) a restart only logs what it would start.

The IDE app

zig build ide (or zig-out/bin/ide DIR) opens a folder: Files and Search tabs on the left, a Welcome tab and source tabs in the middle, the Output panel below, all in one dock so any of them can be dragged. Shortcuts: Ctrl+S save, Ctrl+F / Ctrl+H find and replace in the file, Ctrl+Shift+F find in project, Ctrl+` terminal, Ctrl+Shift+F6 restart the IDE, Ctrl+Shift+F5 build and restart, F5 save all and zig build run, Ctrl+B zig build, Ctrl+Shift+T zig build test. Double-clicking an error in Output opens the file at that line. Headless checks use ZIGUI_SCRIPT with open PATH[:LINE], search TEXT, sleep MS, click, type and key.

Zig without a language server

Two UI-free pieces read Zig with std.zig.Ast only, so completion works offline and with no configuration:

  • ide.zig_index.Index (init(gpa, io, std_dir)): parseBuffer(text, dir) parses the file being edited; membersOf(file, &.{"std","mem"}, &out) lists the names a path is followed by (Member{name, kind, detail} with kinds fn, const, var, mod, type, field, enum); topLevel(file, &out) lists a file's own names. It follows @imports (std, relative .zig files), aliases (const m = std.mem;), and containers declared in the file, and lists only pub names of other files. It also knows a little about values: a function's parameters (b in fn build(b: *std.Build)), locals declared above the cursor (const exe = b.addExecutable(...), from the called function's return type or a type annotation), typed fields, and @This(), with *T, ?T and !T looked through. membersOfAt/lookupAt take the byte offset the path was written at. Generic types (std.ArrayList(u8)) and anything needing real type analysis are left to a language server. Library files are parsed when first needed and cached.
  • ide.zig_complete.ZigCompleter: a Completion provider over the index. After name. it lists members; after @ the builtin functions with signatures; otherwise the file's top-level names, keywords and primitive types. It answers only for editors whose language is Zig. locateStdDir(gpa, io) asks zig env for the library path (null if zig is not on PATH), and setDir(editor, dir) tells it where a file lives so relative imports resolve.

ZigCompleter is also the provider for hover (a declaration's signature and /// doc comment, or a builtin's signature) and signature help (the parameter list of the function being called, so typing @Vector( keeps showing len and Element). Index.lookup(file, path) finds one declaration (Member.doc holds its raw doc comment).

In the app: documents.enableCompletion(completion, zig_completer) attaches the suggestion list to every editor it opens, and documents.enableHints(hover, signature) the hover and signature help. Language servers will add to these answers, not replace them.
