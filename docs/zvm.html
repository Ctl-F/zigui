Zig versions (ZVM)

The IDE uses ZVM, the Zig version manager, to install Zig versions, switch between them, and use the version each project asks for. ZVM does the work; the IDE runs it (its progress shows in the Output panel) and keeps its own state in sync. Nothing here is required: without ZVM the IDE uses whatever zig is on PATH.

First start: is ZVM installed?

At startup the IDE looks for ZVM in $ZVM_INSTALL, then on PATH, then in ~/.zvm/self ($ZVM_PATH replaces ~/.zvm). If it is missing, a box asks whether to install it and shows the exact line it would run: curl -fsSL https://www.zvm.app/install.sh | bash (Linux, macOS) or irm https://www.zvm.app/install.ps1 | iex in PowerShell (Windows). Install ZVM runs ZVM's official installer in the Output panel and then picks ZVM up without a restart. Not now asks again next start; Don't ask again writes zvm-declined in the IDE's settings folder (~/.config/zigui-ide; delete it to be asked again). Zig > Install ZVM... asks at any time.

The version button and the picker

The right end of the status bar shows Zig 0.17.0, the version zig on PATH runs (Zig: no ZVM or Zig: none selected otherwise). Clicking it, or Zig > Switch Zig Version..., opens a picker of the installed versions (newest first, master on top) with the one in use and the one the project asks for marked, and Install another version... at the end. Choosing a version runs zvm use VERSION, then restarts the IDE on the same project (and files) so completion, the language server and builds all use it. Note that zvm use changes zig for the whole machine, not just this window: that is how ZVM works.

Zig > Install Zig Version... lists the versions ZVM can install (it asks ZVM, which needs the network; the list says "with ZLS" where a language server build exists). Choosing one runs zvm install VERSION (with --zls when a ZLS build exists), then offers to switch to it. Zig > Install ZLS for This Zig Version runs zvm install CURRENT --zls, which adds only the language server, then restarts: this is the fix for "using zls 0.16.0 for Zig 0.17.0".

A project's version

A project asks for a Zig version in either place (the first found wins):

  • .zigversion in the project root: its first line, such as 0.16.0 (or master).
  • .minimum_zig_version = "0.16.0" in build.zig.zon.

Only plain versions and master count; a development string such as 0.17.0-dev.12+abc is ignored. When a project opens, before anything reads zig env:

  • ZVM has the version and it is already in use: nothing happens (no process is started).
  • ZVM has it but another is in use: the IDE runs zvm use VERSION and starts with it.
  • ZVM does not have it: a box offers Install and switch (install, zvm use, restart) or Not now.

New projects under a version

With ZVM and at least one Zig installed, File > New Project... adds a step after the template: a picker of installed versions (the one in use first). The project is made with that version (zig init runs from ~/.zvm/VERSION/zig, so the manifest matches) and a .zigversion file records it, so opening the project later selects the version again.

How it works

PieceWhere
ide.zvmUI-free: locate, installed and current (read from ~/.zvm: every VERSION/zig, and where bin points, so no process is started), projectVersion, autoSwitch, Fetcher (the installable list from zvm ls-remote --json on a worker thread), command builders (installArgv, useArgv, install_script_argv).
ide.zig_versions.VersionsThe IDE side: status-bar button, pickers, questions, running ZVM in the Output panel and acting when it finishes (poll() each loop iteration).
QuickPick, MessageBoxThe picker and the yes/no boxes.

For headless checks, ZIGUI_ZVM_INSTALL="shell command" replaces the install script, and commands zig.switch_version, zig.install_version, zig.install_zls, zig.install_zvm can be run with cmd NAME. ZVM prints an upgrade notice around its output; the IDE asks for --color off and reads only the JSON it needs.
