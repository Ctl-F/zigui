Events, commands, shortcuts

Events

Input becomes Events dispatched through the tree in three phases: capture (root down to the target), target, then bubble (target up to the root). Kinds:

KindNotes
pointer_down, pointer_up, pointer_movePosition in x,y (window) and local_x,local_y (relative to the listening node); button (1 = left); clicks (2 = double click). While a button is held, the node that was pressed keeps receiving the pointer (pointer capture).
pointer_enter, pointer_leaveHover. Do not bubble.
clickPress and release on the same node (or within its subtree).
wheeldx, dy.
key_down, key_upkey, mods, repeat. Delivered to the focused node.
text_input, text_editingTyped/pasted text and IME composition; text is valid only during dispatch.
focus_in, focus_outDo not bubble.
commandA named command ran; text is its name.

Listening

try ui.tree.addListener(node, .{
    .kind = .pointer_down,
    .callback = .bind(&app, App.onDown),
});

fn onDown(self: *App, ev: *zigui.event.Event) void {
    if (ev.button != 1) return;
    self.start_drag(ev.x, ev.y);
    ev.stopPropagation();       // ancestors do not see this event
}
  • A listener with .capture = true runs during the capture phase, before the target sees the event. The builder uses this to intercept clicks on its design surface.
  • ev.stopPropagation() stops further listeners on other nodes; ev.markHandled() tells the toolkit a default action (such as focusing, or moving the caret) should not run.
  • Callbacks may destroy nodes: destruction is deferred until dispatch ends, and handles you hold stay safe to check.
  • Attaching a pointer listener makes a node interactive (it takes part in hit-testing and hover).

Focus

One node has keyboard focus (ui.focused(), ui.setFocus(h), ui.setFocus(null)). A node must have flags.focusable = true (widgets that take keys set this); Tab and Shift+Tab move between focusable nodes in tree order, adjusted by node.tab_index.

Focus scopes trap focus for dialogs and menus:

if (ui.pushFocusScope(dialog_root, true)) { ... }   // true: also block pointer input outside
...
ui.popFocusScope();                                  // focus returns to where it was

Making your own nodes clickable

try ui.makeClickable(row, .{ .label = "Open file", .on_click = .bind(&app, App.open) });

This sets role, label, focusability, a pointer cursor, and click/Enter/Space activation.

Commands

A command is a named action ("file.save") that buttons, shortcuts, menus, and code can all run.

_ = try ui.registerCommand("file.save", .{
    .title = "Save",
    .run = .bind(&app, App.save),
    .enabled = true,
    .repeat = false,          // holding the shortcut does not re-run it
});

_ = ui.invokeCommand("file.save");
_ = ui.setCommandEnabled("file.save", app.dirty);

A button can run a command directly: ui.add(Button, parent, .{ .text = "Save", .command = "file.save" }). It is disabled automatically while the command is disabled.

Shortcuts

try ui.bindShortcut("mod+s", "file.save", .app, null);
try ui.bindShortcut("ctrl+k ctrl+c", "edit.comment", .app, null);          // a two-key sequence
try ui.bindShortcut("alt+up", "builder.up", .panel, preview_panel_node);   // only while focus is inside that panel
  • mod is Ctrl on Linux/Windows and Cmd on macOS.
  • Scopes, least to most specific: .app, .window, .panel (focus inside a node's subtree), .widget (that node itself focused). The most specific matching binding wins; a binding whose command is disabled is skipped so a broader one can take over.
  • Sequences wait up to 1.5 s for the next chord; a key that completes nothing is swallowed so a dead chord never types.
  • In a text field, unmodified printable keys never trigger shortcuts.
  • bindShortcut returns error.Conflict if the sequence is a prefix of another binding in the same scope; use rebindShortcut to replace.

Keymap files

const report = ui.loadKeymap(
    \\ctrl+s = file.save
    \\window: ctrl+k ctrl+c = edit.comment
    \\ctrl+q = none            # unbind
);

Only app and window scopes can be written in text. Bad lines are skipped and counted in the report. ui.shortcutText("file.save", &buf) gives the text to show in a menu.

Cursors

Set node.cursor (.default .text .pointer .resize_horizontal .resize_vertical); ui.cursor() returns the one for the node under the pointer, and the platform shim applies it (sdl.setUiCursor(ui.cursor())).
