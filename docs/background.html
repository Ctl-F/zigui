Background work and processes

The UI core is single-threaded: only the UI thread touches the tree and widgets. Anything slow — reading a pipe, searching files, talking to another program — runs on a worker thread that hands its results to the UI thread through a queue.

worker.Queue

var q: zigui.worker.Queue(Line) = .{ .gpa = gpa, .wake = sdl.wake };
defer q.deinit();

// on a worker thread
try q.push(line);                      // also calls `wake`, so a sleeping loop runs

// on the UI thread, once per loop iteration
var batch: std.ArrayListUnmanaged(Line) = .empty;
defer batch.deinit(gpa);
q.drain(&batch);                       // everything queued so far, in order per producer
for (batch.items) |item| { ... }
batch.clearRetainingCapacity();

The lock is a tiny spin lock (the critical sections are an append or a swap), so no Io instance is needed. q.pending() says whether anything is waiting. The window loops pass sdl.wake (also set as ui.wake).

process.Runner

Run a child process with its output delivered as events, without blocking:

const run = try zigui.process.Runner.start(gpa, io, .{
    .argv = &.{ "zig", "build", "test" },
    .cwd = project_dir,        // optional
    .stdin = false,            // true to keep a pipe for writeStdin
    .wake = sdl.wake,
});
defer run.destroy();           // stops the process if it is still running, joins the threads

// each loop iteration
var batch: std.ArrayListUnmanaged(zigui.process.Event) = .empty;
run.drain(&batch);
for (batch.items) |*e| {
    switch (e.*) {
        .chunk => |c| show(c.stream, c.bytes),   // .stdout or .stderr: kept separate
        .exited => |term| report(term),
    }
    e.deinit(gpa);                               // chunks own their bytes
}
batch.clearRetainingCapacity();
CallPurpose
start(gpa, io, options)Spawn with piped stdin/stdout/stderr; a reader thread per output stream and one that reaps the child.
drain(list)Move the queued events onto list (UI thread).
finished()The process has exited and its .exited event is queued.
writeStdin(bytes)Write to the child (needs .stdin = true).
stop()Ask it to end (SIGTERM).

Limits: no stop on Windows yet; output is read in chunks of up to 4 KiB with no line splitting (a front end splits lines — see the Output panel); no pseudo-terminal, so programs that expect a terminal behave as if piped (for those, use the terminal's Pty).

Timers

ui.setTimer(delay_ms, callback) runs a callback once on the UI thread, delay_ms after the current time (at the next ui.tick that is due), and returns an id; ui.cancelTimer(id) cancels one that has not fired. The event passed is a command event with no name. ui.nextWakeMs() includes pending timers, so an idle event loop sleeps exactly until the next one. Hover tooltips and signature-help refreshes use them.
