Tests panel

View > Tests (a tab beside Output) lists every test in the project's .zig files, grouped by file, and runs them from the IDE. Each test shows a status: [ ] not run, [..] running, [ok], [FAIL] or [skip], and each file shows how many of its tests failed. Select a test to see what it printed and why it failed (the error, the stack trace, a memory-leak report) on the right; double-click it to open its source at the test line.

Finding the tests

The files are read, nothing is run: a worker thread parses each .zig file with std.zig.Ast and lists the test "name", test identifier (shown as decl name) and unnamed test {} declarations, including ones inside const X = struct { ... }. It rescans when the panel opens, after a save, and with Refresh; statuses of tests that are still there are kept.

A single test or a file runs in one of two ways. If your build.zig accepts -Dtest-filter (the IDE checks once with zig build --help; add const filters = b.option([]const []const u8, "test-filter", "Skip tests that do not match any filter") orelse &[0][]const u8{}; and pass .filters = filters to b.addTest, as Zig's own build does), it runs zig build test -Dtest-filter=NAME, which works for anything the build can build, including files that need modules. Without that option it runs zig test FILE [--test-filter NAME], which works when the file's imports stay inside its own folder and fails with a compiler message otherwise (shown in the output pane). Run Failed needs the option, since it passes one filter per failed test.

What the statuses are based on

  • zig test runs the test program directly, which prints a line per test as it runs, so statuses appear live, including [skip]. A test that printed OK but then reported leaked memory is marked failed; a test that crashed the program is marked failed.
  • zig build test runs the program through the build system, which reports only a summary and a block for each failing test. So a test is marked [..] while it runs and, when the run ends, [ok] unless it was named as failed. A skipped test therefore shows [ok] in a build run.
  • Tests are matched to reports by name: the compiler names a test FILE.test.NAME (FILE is the file's path in its module with dots), FILE.decltest.NAME or FILE.test_N for an unnamed one. Two files with the same base name are told apart only by that path, so identically named tests in them can be confused.
  • If the run never reaches the tests (a compile error), the statuses stay [ ] and the output pane shows the compiler's message.

Code

ide.test_scan is UI-free: scan, fullName, matches and Parser (modes .direct and .build, fed with the output as it arrives). ide.TestPanel is the panel (create, refresh, poll, run(scope), stop). Headless: cmd view.tests. The existing Build > Run Tests (Ctrl+Shift+T) still runs zig build test into the Output panel.
