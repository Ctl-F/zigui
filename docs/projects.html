Opening and creating projects (in the IDE)

A project is a folder; the IDE needs nothing more (Zig projects get build commands from their build.zig, but any folder works for editing, search and the terminal).

Open Project

File > Open Project... shows the folder chooser, starting beside the current project. Choosing a folder saves everything, writes this project's session, and starts a new IDE window on that folder (which reopens that folder's own session); this window closes. (One window holds one project; a window that could switch projects in place is not built.)

New Project

With ZVM and a Zig installed, the template step is followed by a choice of Zig version, recorded in .zigversion; opening a project later selects the version it asks for.

File > New Project... asks for a place and a name in the same dialog (the name becomes the folder, the package and the program, so it is an identifier of up to 32 letters, digits and underscores), then offers templates:

TemplateWhat you get
zigui appA window application whose contents come from a UI document. build.zig and build.zig.zon (made by zig init, so the package fingerprint is real, with zigui added as a path dependency), main.zig (window, fonts, loads ui/main.ui.zon from the working directory, registers the actions), ui/main.ui.zon (a label and a button), ui/main.zig (Main with the button's handler onHelloClick), the generated ui_actions.zig and .zigide/actions.zon. zig build run runs it; open the .ui.zon in the IDE and the Events tab already lists the handler. Needs the zigui source: it is found from the IDE's executable (<root>/zig-out/bin/ide) or ZIGUI_ROOT; without it the entry is greyed out.
Zig projectWhat zig init makes: build.zig, build.zig.zon, src/main.zig, src/root.zig.
Empty folderA README only, for any language.

zig must be on PATH for the two Zig templates; a failure shows zig init's message in the status line. An existing empty folder is fine; a folder with files in it is refused. The new project then opens in a new window, like Open Project.

Using zigui from your own project

The zigui checkout now has a build.zig.zon, so another project can depend on it by path and import its modules (zigui, zigui_sdl, zigui_stb, zigui_gpu) the way the generated build.zig does:

// build.zig.zon
.dependencies = .{ .zigui = .{ .path = "../zigui" } },

// build.zig
const zigui = b.dependency("zigui", .{ .target = target, .optimize = optimize });
exe.root_module.addImport("zigui", zigui.module("zigui"));
exe.root_module.addImport("zigui_sdl", zigui.module("zigui_sdl"));
exe.root_module.addImport("zigui_stb", zigui.module("zigui_stb"));

(SDL3's development files must be installed.)

The pieces

ide.new_project: create(gpa, io, parent, name, template, zigui_root, &report), templates, validName, findZiguiRoot, patchManifest. The zigui app's files are in src/ide/templates/zigui_app/ (.tmpl, with @@NAME@@ for the project name), embedded in the IDE.
