Continuous error checking

The IDE can keep the compiler itself running in the background and show its errors as you work. It runs zig build --watch (with -fincremental, so after an edit only what the edit touched is recompiled) and reads the errors of every rebuild.

What it adds to the language server

zls reports syntax and ast-check errors (undeclared names, unused variables). The compiler also reports everything semantic analysis finds: type mismatches, wrong argument counts, missing fields, comptime failures, for the build graph as it is configured. The price: it builds (and installs) your project after each save, and only files the build reaches are checked. Both sources can be on at once; zls answers as you type, the compiler after you save.

Using it

  • Build > Check Errors Continuously starts and stops it (or the Start/Stop button in the Problems panel, next to Output). The panel header says what is happening (Watching, incremental: 1 errors, 0 warnings (rebuild 3)).
  • Errors and warnings of the latest rebuild appear as wavy underlines (the compiler's ^~~~ marker gives the length), in the Problems list (double-click or Enter opens the spot) and as build: message when you rest the pointer on the underlined word.
  • A rebuild with no errors clears everything. Files outside the project (the standard library, dependencies) are not marked.
  • Squiggles follow edits until the next rebuild; after a save the compiler's answer replaces them.
  • The project needs a build.zig; otherwise the panel says so.

Settings

KeyDefaultMeaning
.build_watchfalseStart it when the project opens; changing it in the settings file starts or stops it live.
.build_watch_step""The build step to watch (zig build STEP); "" is the default step. Pick a step that compiles what you edit (for a library, its test step).
.build_watch_incrementaltruePass -fincremental. Turn it off if the incremental compiler misbehaves on your code.

How it works

ide.build_watch.Watcher runs the command through platform/process.zig and feeds the output to a Collector. A rebuild always ends with a Build Summary: line (also when nothing failed), so the located diagnostics (path:line:col: error: ...) printed since the previous summary are one Result; the line after a diagnostic is the source and the next one the caret line. Duplicate diagnostics (several steps compiling one file) count once and notes are skipped. ide.WatchPanel is the Problems panel: it puts the result in a TreeView, sets editor decorations (owner slot 2; 1 is the language server) and provides a hover provider.

The build server protocol (--listen=-) would give structured errors and rebuild notifications, but it is a binary protocol meant for the build runner's own tooling and changes between releases; the text output used here is the same format as the Output panel reads. Headless: cmd build.watch_toggle.
