Git panel

View > Git (a tab beside Files) shows the repository the project is in and lets you review and commit changes without leaving the IDE. It uses the git program, so your configuration, credential helpers and ssh agent work as in a terminal. When the project is not inside a repository (or git is not installed) the panel shows a one-line note instead.

What it shows

  • The branch, its upstream and how far ahead or behind it is (master -> origin/master ahead 1, behind 0), or (no upstream).
  • The changes in groups: Merge Conflicts (only when there are any), Staged Changes, Changes and Untracked Files. A file with both staged and unstaged edits appears in both groups. Each row has a status letter (M modified, A added, D deleted, R renamed, U untracked) and a renamed file also shows its old name.
  • The diff of the selected file below the list: added lines tinted green, removed lines red and hunk headers blue. Untracked files show as all-added. Diffs are cut at 1 MiB. Double-click a row to open the file in an editor.

What it does

ButtonRuns
Stage / Unstagegit add -- FILE / git restore --staged -- FILE (git rm --cached in a repository with no commits yet) for the selected file
DiscardAfter a confirmation: git restore -- FILE (changes are lost) or git clean -f -- FILE (an untracked file is deleted)
Stage All / Unstage Allgit add -A / git restore --staged -- .
Commitgit commit -m MESSAGE with the text in the message field; it asks for staged files and a message first, and clears the field on success
Stash / Pop Stashgit stash push -u [-m MESSAGE] (untracked files included; the message field is used as the stash message if it has text) / git stash pop; the panel shows how many stashes exist
Push / Publish Branchgit push, or git push -u origin BRANCH when the branch has no upstream yet
RefreshReads the status again

The result of the last action (or git's complaint) shows in a line at the bottom of the panel. The panel refreshes after each action, when a file is saved in the IDE, when you open it with View > Git, and every five seconds. Only one git command runs at a time; pressing a button while one runs says so.

Credentials: git runs with GIT_TERMINAL_PROMPT=0, so a push that needs a password fails with a message instead of waiting on an invisible prompt. If it fails that way, push once from a terminal (or set up a credential helper or ssh key).

Code

ide.git is UI-free: Git (a worker thread running git -C ROOT ...: submit(job), poll(), run(args)), parseStatus for git status --porcelain=v1 -z --branch and diffLineKind. ide.GitPanel is the panel (create(ui, parent, io, root, .{ .on_open, .overlay, .environ, .wake }), refresh(), poll()). The diff uses the editor decoration kind added_line (green; the theme's line_added) beside error_line and note_line. Headless: cmd view.git.

Not included: history, blame, branch switching or creation, merges and conflict resolution, partial (hunk) staging, pull.
