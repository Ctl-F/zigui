UI documents (ZON)

A UI can be described in a text file and instantiated at runtime (or embedded with @embedFile). The same format is what the builder edits. Files hold only what differs from defaults, so they stay small and diff well.

Format

.{
    .version = 1,
    .root = .{
        .type = "box",
        .style = .{ .direction = .column, .gap = 8, .padding = .{ .left = 12, .top = 12 } },
        .children = .{
            .{ .type = "label", .props = .{ .text = "Hello" } },
            .{ .type = "button", .id = "ok", .props = .{ .text = "OK" }, .on = .{ .click = "confirm" } },
        },
    },
}
KeyMeaning
.typeA widget name (label, button, text_field, code_editor, canvas, scroll_view, split_view, select, tab_view, dock, tree_view, menu_bar) or "box" for a plain container.
.styleSparse Style. Lengths: a number is pixels; .fill, .fit, .auto; percent as the string "50%" (or .{ .percent = 50 }). Enums by name (.direction = .column).
.propsSparse widget props: the widget's Props fields (see each widget page). Content text for text_field and code_editor goes in .text.
.onEvent to action name: .on = .{ .click = "confirm" }. The app supplies the actions.
.idA name to look the live node up by.
.childrenChild nodes. A scroll_view's children go in its content; a split_view takes exactly two.

Loading

var diag: zigui.zon.Diag = .{};
var problem: zigui.uidoc.Problem = undefined;
var doc = try zigui.uidoc.parseDoc(gpa, @embedFile("main.zon"), &diag, &problem);
defer doc.deinit();

var actions: zigui.uiload.Actions = .{};
defer actions.deinit(gpa);
try actions.put(gpa, "confirm", .bind(&app, App.onConfirm));

var inst = try zigui.uiload.instantiate(&ui, ui.tree.root, &doc, .{ .actions = &actions });
defer inst.destroy();

const ok = inst.widget(zigui.Button, "ok").?;      // by id and type
const node = inst.find("ok");                        // or just the node handle
  • A syntax error carries a line and column in diag.
  • instantiate never crashes on a bad document: every unknown prop, wrong value type, unknown enum name, or missing action becomes a Problem (with a path such as props.variant: unknown value 'huge') in inst.problems, and the rest still builds. Set .strict = false to ignore unknown actions (the builder does).
  • instantiateStrict returns error.InvalidDocument if there are any problems.

Building a document in code

Doc is the model the builder edits (zigui.uidoc.Doc): Doc.init(gpa) creates an empty one (a box root), doc.toZon(gpa) writes it out. Edits with undo go through zigui.uiedit.Editor.

The registry

zigui.registry lists every widget by name with its Props and Out schemas. registry.create(ui, "button", parent), setProp(ui, node, "text", value), setStyle(ui, node, "padding.left", value) write by path, mark the right dirty flags, and reject wrong types. Widgets must be listed in registry.widgets to appear in documents and in the builder's palette.
