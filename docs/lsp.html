Language servers

The IDE can talk to a language server (zls for Zig, or any server that speaks the Language Server Protocol over stdio) on top of the offline completion in the IDE page: nothing here is required. If the server is not installed or exits, the editor keeps working and the status line says so.

What it adds

FeatureHow it shows
DiagnosticsWavy underlines (red for errors, amber for warnings, blue for hints) under the reported ranges; hovering one shows its message.
CompletionThe server's items join the suggestion list a moment after the offline ones (Completion.offer).
HoverThe server's text appears in the hover tooltip if nothing else is showing (Hover.offer).
Parameter hintsThe server's signature, with the active parameter emphasized (SignatureHelp.offer).
Go to definitionF12 opens the definition of the name at the caret (any file); Ctrl+click (Cmd+click on macOS) does the same for the name under the pointer (Assist.gotoDefinitionAt(editor, offset)).

Semantic errors that zls does not report (type errors and the rest) can come from the compiler instead: see continuous error checking.

In the IDE app

zig build ide starts zls from PATH when the first Zig file opens, or the program in ZIGUI_ZLS=/path/to/zls. Edits are sent as the whole text 120 ms after typing stops, and always before a request that depends on them.

Which zls is used

With ZVM, Zig > Install ZLS for This Zig Version installs the matching zls (zvm install VERSION --zls) and restarts the IDE.

A zls build only understands the Zig version it was built for, so the IDE asks zig env for the compiler version and looks for a matching zls (same major.minor), in this order: ZIGUI_ZLS / the .language_server setting, PATH, $XDG_DATA_HOME/zls/<version>/zls, ~/.local/share/zls/<version>, ~/.zvm/<version>, ~/.local/bin, /usr/local/bin, /usr/bin. If no build matches, the newest older one is used and the status line says so (“using zls 0.16.0 for Zig 0.17.0 … some answers may be missing”). If none is found at all the status line lists where it looked instead of a bare “FileNotFound”. Implemented in src/ide/zls_locate.zig.

Using it in your own program

const lsp = try zigui.ide.lsp_assist.Assist.create(&ui, io, project_root);
defer lsp.destroy();                       // create it before the Documents; destroy it after
try lsp.addServer(&zigui.syntax.zig, "zig", &.{"zls"});    // language, language id, command line
lsp.wake = sdl.wake;
lsp.completion = completion; lsp.hover = hover; lsp.signature = signature;
lsp.on_open = .bind(&app, App.openAt);   // go to definition: absolute path, 1-based line and column
try completion.addProvider(lsp.completionProvider());
try hover.addProvider(lsp.hoverProvider());
try signature.addProvider(lsp.signatureProvider());
documents.enableLsp(lsp);                  // attaches/detaches editors, reports saves

// every loop iteration
lsp.poll();
// status line: lsp.statusText(), lsp.diagnosticCounts(editor), lsp.gotoDefinition(editor)

Without Documents, call lsp.attach(editor, abs_path) when a file opens, lsp.saved(editor) after saving and lsp.detach(editor) before the editor goes away.

The pieces

  • ide/lsp/jsonrpc.zig: Content-Length framing (frame, Reader that copes with messages split or batched).
  • ide/lsp/client.zig: Client over any byte transport: the initialize handshake (requesting UTF-8 positions; UTF-16 is converted), queued sends until ready, request ids with callbacks and cancel, answers to the requests servers make (configuration, capability registration, progress), didOpen/didChange (full text)/didSave/didClose, diagnostics hook. Also fileUri, pathFromUri, characterOf, byteColOf. UI-free and testable without a process.
  • ide/lsp/results.zig: readers for completion, hover, signature help, locations and diagnostics, accepting every shape the protocol allows.
  • ide/lsp_assist.zig: Assist, the glue to editors and the process (platform/process.zig with a stdin pipe).

Limits (first iteration)

One server per language, started lazily and never restarted after it exits; no incremental sync, rename, code actions, formatting or workspace symbols yet; a server's snippet completions are turned off (plain text only).
