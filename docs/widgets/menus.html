Menus: popup, context, and menu bar

A menu is a popup list drawn over everything else. One is open at a time. It closes when an item is picked, on Escape, or when the pointer is pressed outside it. While open it holds keyboard focus (Up/Down/Home/End move, Enter or Space pick, Tab stays inside) and returns focus when it closes. The Select drop-down, the menu bar, and right-click menus are all this one thing.

Popup and context menus

const items = [_]zigui.menu.Item{
    .{ .label = "Cut", .command = "edit.cut" },
    .{ .label = "Copy", .command = "edit.copy" },
    .{ .separator = true },
    .{ .label = "Properties", .enabled = false },
};
try ui.openMenu(&items, x, y, .{ .on_pick = zigui.menu.PickHook.bind(&app, App.onPick) });

fn onPick(self: *App, index: usize) void { ... }   // called after the menu has closed

A right-click menu is a listener that opens one at the pointer:

try ui.tree.addListener(editor_node, .{ .kind = .pointer_down, .callback = .bind(&app, App.onDown) });

fn onDown(self: *App, ev: *zigui.event.Event) void {
    if (ev.button != 3) return;                      // 1 left, 2 middle, 3 right
    self.ui.openMenu(&items, ev.x, ev.y, .{}) catch {};
}

Item

FieldMeaning
labelText (copied).
commandA registered command name: picking runs it, the item is enabled only while the command is, and the command's shortcut is shown on the right.
enabledGreyed out and unpickable when false.
separatorA divider line.
checkedA check mark before the label.
userYours.

Options

OptionMeaning
on_pickA PickHook called with the picked item's index. Items with a command run it too.
anchorA rectangle (window coordinates) the menu drops from: below it, or above if there is no room. Without it the menu opens at (x, y).
ownerThe opener's node. Pressing it while the menu is open closes the menu and does not reopen it.
min_widthMinimum width (a select uses its own width).
focus_indexWhich item starts focused.

The menu is kept inside the window. ui.closeMenu() closes it; ui.menuOpen() tells you if one is open.

MenuBar

const bar = try zigui.MenuBar.create(&ui, parent, .{});
defer bar.destroy();
try bar.addMenu("File", &.{
    .{ .label = "Save", .command = "file.save" },
    .{ .separator = true },
    .{ .label = "Quit", .command = "app.quit" },
}, null);
try bar.addMenu("Edit", &.{ .{ .label = "Undo", .command = "edit.undo" } }, null);

Clicking a title opens its menu below it; while one is open, moving over another title switches to it; clicking the open title again closes it. The optional last argument is a PickHook for that menu. Like Form, the bar is a heap object you destroy. Put bar.node in your layout (it is a row; pass .style in the options to size it).

Limits

  • No submenus, no icons, no keyboard mnemonics (Alt+letter) or arrow-key switching between bar menus yet.
  • Long menus do not scroll; keep them shorter than the window.
