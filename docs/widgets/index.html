Widgets

A widget is behavior attached to a node. Create one with ui.add(Widget, parent, options); it returns a pointer you can keep (valid until the widget is destroyed). Every widget has props (state you control), out (what the toolkit reports), and an Options struct for creation. All text you pass is copied.

Common patterns

Styling a widget

Every Options has a style: Style (see Layout):

_ = try ui.add(zigui.Button, parent, .{ .text = "OK", .style = .{ .width = .px(120) } });

Reacting

// 1. a callback in the options
_ = try ui.add(zigui.Button, parent, .{ .text = "OK", .on_click = .bind(&app, App.ok) });
// 2. polling out after ui.update()
if (button.out.clicked) { ... }

Changing a widget later

label.setText("Saved");        // setters mark the right dirty flags
button.setEnabled(false);

Widgets in UI documents

The registry (zigui.registry) gives every widget a name and a schema, which is how UI documents, the builder and forms create and edit them without compile-time knowledge. When you add a widget, add it to registry.widgets, to the nav in docs/nav.js, and write its page.
