Terminal

A terminal emulator widget: it draws the screen a program produces and turns keys, text, mouse and paste into the bytes the program expects. It is made of three parts you can use separately.

PartWhat it is
zigui.vt.Screen (terminal/vt.zig)The emulator: feed it bytes, read the grid. No UI, no process.
zigui.Terminal (widgets/terminal.zig)The widget: draws a Screen, sizes it to the node, handles input. Knows nothing about processes.
zigui.pty.Pty (platform/pty.zig)A pseudo-terminal with a program (a shell) on the other end. Linux for now.

The widget

const term = try ui.add(zigui.Terminal, parent, .{
    .style = .{ .grow = 1 },
    .on_write = .bind(&session, Session.send),      // fn (*Session, bytes) void: what the user typed
    .on_resize = .bind(&session, Session.resized),  // fn (*Session, cols: u16, rows: u16) void
});
term.feed(bytes_the_program_printed);

A focused terminal asks the platform for text input (Ui.textInputRect returns its cursor cell), so typed characters and IME composition arrive; the window loop must start text input when that is non-null, as every example does.

The widget works out its size in character cells from its node and the mono font, and calls on_resize when it changes (and once when first laid out). feed shows output and sends answers to the program's queries (cursor position, device attributes) through on_write. title() is the program's window title; out.title_changed says it was set. Options: scrollback (lines of history, default 5000), size, pass_function_keys. Other methods: paste(text), scrollBy(lines), selectedText(gpa), clear().

Input

You doWhat happens
Type textSent as is (UTF-8).
Enter, Tab, Shift+Tab, Backspace, Escape, arrows, Home/End, Insert, Delete, Page Up/DownThe usual sequences (arrows and Home/End use the application form when the program asked for it); with Shift, Alt or Ctrl they carry the modifier (ESC [1;5C).
Ctrl+letter, Ctrl+Space, Ctrl+[ \ ] /The control characters (Ctrl+C is 0x03).
Alt+letterEscape-prefixed (readline's word movement).
F1–F12Left to the application's shortcuts (F5 builds, F12 goes to definition) unless pass_function_keys is off.
Ctrl+Shift+C / Ctrl+Insert, Ctrl+Shift+V / Shift+InsertCopy the selection; paste (wrapped in ESC [200~ when the program enabled bracketed paste). Other Ctrl+Shift combinations stay with the application.
Wheel, Shift+Page Up/Down, Shift+Home/EndScroll the history. The view stays on the same text while output arrives. On the alternate screen (less, vim) the wheel sends arrow keys.
Drag, double-click, triple-clickSelect text, a word, a line.
Mouse in a program that asked for reportsSent to it (SGR encoding); hold Shift to select instead.

What the emulator understands

UTF-8 text with wide (CJK, emoji) characters; BS, HT, LF, CR, BEL; cursor movement and positioning; erase, insert and delete of characters and lines; scroll regions; colors (16, 256, true color) and bold, dim, italic, underline, inverse, strikethrough; the alternate screen; save and restore cursor; tab stops; cursor-key, bracketed-paste, autowrap, cursor-visibility and mouse-report modes; window titles; device and cursor-position reports. Scrolled-off lines go to a ring buffer of history (not on the alternate screen). Not yet: combining characters (dropped), other character sets, sixel graphics, blinking text, cursor shapes.

The Pty

const pty = try zigui.pty.Pty.open(gpa, .{ .argv = &.{"/bin/bash"}, .cwd = dir, .cols = 80, .rows = 24,
                                            .environ = init.environ_map, .wake = sdl.wake });
defer pty.close();
try pty.write("ls\n");
pty.resize(120, 30);
var batch: std.ArrayListUnmanaged(zigui.pty.Event) = .empty;
pty.drain(&batch);        // .data (bytes for the emulator) and .exited (status)

The program runs in its own session with the pseudo-terminal as its controlling terminal and as stdin, stdout and stderr, so it behaves as in a real terminal: prompts, colors, line editing, full-screen programs. stdout and stderr arrive merged, in order, on the one stream a terminal has; use process.Runner (the Output panel) when you need them separate. TERM=xterm-256color and COLORTERM=truecolor are set. Closing sends SIGHUP to the process group. Implemented with raw Linux system calls (no libc); other systems return error.Unsupported from open.

The IDE's terminal panel wires the three together. Code-only widget (not in the toolbox).
