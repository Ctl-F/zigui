FileDialog

A file dialog drawn by the toolkit, so it looks and behaves the same on every platform and can be tested: a modal panel with a path field, a list of the folder's entries, and OK / Cancel. It chooses a folder, an existing file, a file name to save to, or the name of a new folder inside an existing one.

const dialog = try zigui.file_dialog.FileDialog.create(&ui, io, ui.tree.root);   // hidden until shown
defer dialog.destroy();
dialog.show(.{
    .title = "Open project folder",
    .mode = .open_folder,                       // .open_folder, .open_file, .save_file, .new_folder
    .start_dir = "/home/me/projects",
    .home = "/home/me",                         // shows a Home button
    .on_result = .bind(&app, App.opened),       // fn (*App, path: []const u8) void (absolute path)
});
ModeResult
open_folderThe selected sub-folder, or the folder shown if nothing is selected. Files are not listed.
open_fileThe selected file (suffix limits the list, e.g. ".zig"); choosing a folder opens it.
save_fileFolder shown + the typed name.
new_folderFolder shown + the typed name (no slashes); the dialog does not create it.

Using it

  • Click selects; double-click or Enter on a folder opens it (on a file it accepts, in the modes that choose files). Up goes to the parent, Home to the home folder, and the path field takes a typed path (Enter goes there; a bad one says "cannot open that folder" and stays). Hidden toggles dot-files. Folders are listed first, then files, each in name order ignoring case; symbolic links to folders count as folders.
  • OK or Enter in the name field accepts; Cancel or Escape closes without calling the hook. A missing selection or name is reported in red in the dialog.
  • While it is open it holds a modal focus scope: the rest of the window gets no input, and the area outside the panel is dimmed.

show can be called again with new options to reuse the dialog; close() hides it; navigate(path) and accept() are available to drive it from code. Code-only widget.
