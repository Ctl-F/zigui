QuickPick

A quick-pick palette: a modal box near the top of the window with a query field above a short list of the best matches among many items (files, symbols, commands). Typing narrows and ranks the list; it is the “go to anything” box of other editors. The IDE's Ctrl+, is built on it.

const qp = try zigui.quick_pick.QuickPick.create(&ui, ui.tree.root);   // hidden until shown
defer qp.destroy();
qp.show(.{
    .placeholder = "Go to file, function or type",
    .items = items,                         // []const quick_pick.Item (borrowed)
    .on_pick = .bind(&app, App.picked),     // fn (*App, index: usize) void
});
qp.setItems(more);                          // while open: the query stays, the list refilters
qp.setStatus("indexing...");                // a line under the list
Item fieldMeaning
labelMatched against the query (completion.matchScore: prefix, then case-insensitive prefix, then letters in order) and shown first.
detailShown after the label (a path, a kind); not matched.
groupBreaks ties between equal matches, lower first (the IDE uses 0 for the project, 1 for the standard library).
  • Best matches first, then group, then shorter labels. At most 40 rows are shown; an empty query shows the first items in the order given. Matching runs over all items on every keystroke, which is fine for tens of thousands.
  • Up / Down / PageUp / PageDown move the selection, Enter or a double-click picks, Escape or a click on the dimmed area closes. While open it holds a modal focus scope.
  • The hook gets the picked item's index into items, after the box has closed.
  • items and their strings are borrowed: keep them valid until the next setItems or close.

External ranking

With .external = true and .on_query = .bind(&app, App.query) (fn (*App, query: []const u8) void) the box does not filter: it shows the items as given (at most 40) and asks the hook for a new list whenever the query changes (and once at show); the hook answers with setItems. The documentation search uses this to rank by doc comments.
