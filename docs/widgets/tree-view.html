TreeView

A scrolling outline of expandable items: file trees, document structure, symbol lists. Items are added from code and referred to by a stable u32 id. In UI documents (and the builder, which also uses one for its outline) the items come from the items prop, a text with one item per line and two spaces (or a tab) of indentation per level.

const tv = try ui.add(zigui.TreeView, parent, .{
    .style = .{ .grow = 1 },
    .on_select = .bind(&app, App.onSelect),
    .on_activate = .bind(&app, App.onOpen),
});

const src = try tv.addItem(zigui.tree_view.no_item, "src");           // top level
const main = try tv.addItem(src, "main.zig");                        // child of src
tv.setUserData(main, file_index);                                    // your own value
tv.setExpanded(src, true);

fn onSelect(self: *App, _: *zigui.event.Event) void {
    const item = self.tree.selected();
    if (item != zigui.tree_view.no_item) self.show(self.tree.userData(item));
}

zigui.tree_view.no_item means "none": no selection, or the top level when used as a parent.

.{ .type = "tree_view", .props = .{ .items = "src\\n  main.zig\\n  ui\\n    layout.zig\\ndocs" } }

Setting items replaces the items (blank lines are skipped; a line indented deeper than allowed hangs off the previous item). expand_all (default true) expands every item with children when the text is loaded. In code you can still use addItem, but setting items afterwards replaces them.

Interaction

InputEffect
Click a rowSelect it (focuses the tree).
Click the arrow, or double-click a row with childrenExpand or collapse.
Double-click, Enter, SpaceActivate the selected item (on_activate).
Up / Down, Home / EndMove the selection (the tree scrolls to keep it visible).
LeftCollapse the selected item, or select its parent.
RightExpand the selected item, or select its first child.
Wheel, scrollbarScroll (it contains a ScrollView).

Collapsing an item that contains the selection moves the selection to that item.

on_togglenullAn item was expanded or collapsed.

Limits

  • Rows are real nodes, rebuilt after structural changes: thousands of items are fine, hundreds of thousands are not (no virtualization yet).
  • Rows show one line of text; no icons, checkboxes, inline rename, or built-in drag and drop yet. Use rowRect/itemAt to build drag and drop.
  • There is no model interface: the tree holds its own copy of items. Keep your data in sync by calling the methods above.
