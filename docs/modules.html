Dependencies and C modules in the index

Ctrl+, (go to anything) and the documentation search include the code your build brings in, not just your own files and the standard library. Use the x: prefix to search only these (x:api, x:m:open). They show as dep/NAME/... (packages), module/NAME/... (modules from outside the project folder) and c/HEADER.h (translated C), and open read-only.

What is found

SourceHow it is found
Packages in build.zig.zon.dependencies entries: a .path is read relative to the manifest; a .hash is the folder <zig global cache>/p/<hash> (what zig fetch and the build download; the cache folder comes from zig env). A package's own build.zig.zon is followed (up to three levels). A package that is not fetched yet is skipped. Every .zig file in the package is indexed (public declarations only; test, example, docs and similar folders are skipped; at most 6000 files per package).
Modules from outside the projectb.addModule("name", .{ .root_source_file = b.path("../shared/src/root.zig") }) (and createModule): when the file is outside the project folder, its folder is indexed.
C headersb.addTranslateC(.{ .root_source_file = b.path("c/api.h") }) in the project's or a package's build.zig, with the addIncludePath, addSystemIncludePath and defineCMacro calls made on the same variable. The header is translated with zig translate-c -lc -I... -D... and the result indexed.

The translate-c cache

Translated headers are kept in the IDE's own cache, separate from zls and from zig build: $XDG_CACHE_HOME/zigui-ide/translate-c, ~/.cache/zigui-ide/translate-c or %LOCALAPPDATA%\zigui-ide\translate-c. A file is named HEADER-KEY.zig; the key hashes the compiler path, the header's path, size and modification time, the include folders and the defines. The same inputs find the file with no process started; a change gives a new file (old ones stay; delete the folder to clean up). A header that does not translate leaves HEADER-KEY.failed with the compiler's message so it is not retried at every start. Headers a header includes are not tracked: touch the top header after changing those. Names beginning with _ and the macros every C header drags in from the system headers (INT8_MAX, PRId64, SIZE_MAX, linux...) are left out of the list.

Limits

This reads build.zig and build.zig.zon as text, it does not run the build (zls runs the build with its own runner to be exact). So what is spelled out plainly is seen; paths or options computed in code, generated headers, options chosen on the command line and per-target differences are not. Only the literal text of the include paths and defines is used, and a translation is for the host target.

Setting

.index_dependencies = true in the settings (default) turns this on; false leaves the Ctrl+, index to the project and the standard library. Read at startup. Code: ide.build_modules (translateCalls, moduleDefs, dependencies, Planner), ide.translate_cache, SymbolIndex.startModules.
