Getting started

Requirements

  • Zig 0.17.0.
  • SDL3 development files (pkg-config sdl3 must work) to open windows. The library and zig build test do not need SDL.
  • A TrueType font. The examples look in common system paths on Linux; set ZIGUI_FONT=/path/ui.ttf and ZIGUI_MONO_FONT=/path/mono.ttf to choose. There is no bundled font yet.
  • glslc only if you edit the GPU shaders (zig build shaders); the compiled SPIR-V is committed.

Build and run what exists

zig build test           # all tests, no SDL needed
zig build demo           # IDE-style demo window
zig build builder        # the visual UI builder (edits ./ui.zon)
zig build workbench      # text editor and builder side by side
zig build paint          # paint program on a Canvas
zig build docking        # tabs, splits and floating panels you can drag
zig build ide            # the IDE on the current folder (files, search, editors, build output)
zig build install        # build all examples into zig-out/bin without running

Examples build in ReleaseSafe by default because software rendering in Debug is an order of magnitude slower; pass -Dexample_optimize=debug to change that.

The pieces of an application

zigui does not own your event loop. A program has four parts:

  1. A platform layer (the zigui_sdl module): creates the window, turns OS events into calls on Ui, shows finished frames.
  2. A font backend (the zigui_stb module): loads a font file and hands it to Ui.addFont.
  3. The Ui (the zigui module): the tree, layout, input, and widgets.
  4. A render backend: software_backend.SoftwareBackend (CPU) or the GPU backend in zigui_gpu.

The repository's build.zig exports the modules zigui, zigui_sdl, zigui_gpu, and zigui_stb. The simplest way to start a program today is to copy examples/dedit.zig to a new file and register it with addExample in build.zig.

Step 1: create the Ui and a font

var ui = try zigui.Ui.init(gpa);   // DO NOT MOVE the Ui after adding widgets
defer ui.deinit();

const font_bytes = stb.loadFirst(io, gpa, environ.get("ZIGUI_FONT"), &stb.ui_font_candidates);
defer if (font_bytes) |b| gpa.free(b);
var font: stb.StbFont = undefined;
try font.init(font_bytes.?, 0);
_ = try ui.addFont(font.backend());      // font id 0 is the UI font
A Ui must stay where it was created once widgets exist (widgets keep a pointer to it). Keep it on the stack of main or on the heap; never return it or put it in a growing container. Debug builds panic if it moves.

Step 2: build the tree

const tree = &ui.tree;
tree.get(tree.root).?.style = .{ .direction = .column, .padding = zigui.style.Edges.all(12), .gap = .px(8) };
tree.get(tree.root).?.visual = .{ .background = zigui.Color.rgb(32, 40, 60) };

_ = try ui.add(zigui.Label, tree.root, .{ .text = "Hello" });
_ = try ui.add(zigui.Button, tree.root, .{
    .text = "Save",
    .on_click = .bind(&app, App.save),
});

ui.add(WidgetType, parent, options) creates the node, the widget state, and its listeners, and returns a pointer to the widget. Options are plain structs with defaults; see each widget page.

Step 3: the frame loop

Every iteration: tick timers, run per-frame updates, draw if anything changed, end the frame, then feed in the OS events.

var list = zigui.DrawList.init(commands, glyphs);   // storage allocated once
var renderer = try zigui.software_backend.SoftwareBackend.init(gpa, presenter);
const backend = renderer.backend();

var force = true;
while (running) {
    _ = ui.tick(sdl.ticks());
    ui.update();
    if (force or ui.isDirty()) {
        const px = window.pixelSize();
        try ui.renderFrame(backend, &list, .{
            .pixel_w = px.w, .pixel_h = px.h, .scale = window.scale(),
            .clear = zigui.Color.black,
        });
        force = false;
    }
    ui.endFrame();

    // Sleep until an event arrives, or until a caret blink / animation is due.
    const timeout: i32 = if (ui.nextWakeMs()) |ms| @intCast(ms) else -1;
    var ev = sdl.waitEvent(timeout);
    _ = ui.tick(sdl.ticks());
    while (ev) |e| : (ev = sdl.pollEvent()) {
        switch (e.data) {
            .quit, .close_requested => running = false,
            .resized, .expose => force = true,
            .mouse_move => |m| ui.pointerMove(m.x, m.y),
            .mouse_button => |m| ui.pointerButtonEx(m.x, m.y, @backingInt(m.button), m.down, m.clicks),
            .mouse_wheel => |m| ui.wheel(m.px, m.py, m.x, m.y),
            .pointer_left => ui.pointerLeft(),
            .focus_lost => ui.pointerCancel(),
            .text_input => |t| ui.textInput(t.bytes[0..t.len]),
            .text_editing => |t| ui.textEditing(t.bytes[0..t.len], t.cursor),
            .key => |k| _ = ui.keyHandled(k.key, k.mods, k.down, k.repeat),
        }
    }
}

What each call does:

CallPurpose
ui.tick(ms)Advances time: caret blink, canvas frame timers. Pass a monotonic millisecond clock.
ui.update()Runs widget per-frame work (turning pointer state into out flags, shaping text).
ui.isDirty()True when something needs layout or painting. Skip drawing when false.
ui.renderFrame(...)Layout, paint into the draw list, submit to the backend (damaged area only).
ui.endFrame()Clears per-frame flags such as out.clicked.
ui.nextWakeMs()Milliseconds until the next timer needs a frame, or null to sleep until an event.
ui.pointer*, ui.wheel, ui.key*, ui.text*Input entry points. Coordinates are logical pixels (not device pixels).

Escape-to-quit, text-input enabling for IMEs (ui.textInputRect()), and cursor shapes (ui.cursor()) are shown in examples/builder.zig.
