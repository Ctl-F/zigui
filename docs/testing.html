Testing and debugging

Unit tests

zig build test             # about 500 tests, no window or SDL needed
zig build check-boundary   # part of test: no C-convention code in the core

zig build test prints ui_check warnings and a "failed command" line on purpose (shadow-checker tests); judge success by the exit status and the final test count, not those lines. Tests run against a headless harness with a synthetic test font, so layout and painting are deterministic. A good pattern for a new widget: create a Ui, add the widget, feed events (ui.pointerMove, ui.textInput), call ui.update() and a frame, and assert on out, node rectangles, or draw-list commands. See the tests at the bottom of src/core/ui.zig and src/builder/builder.zig.

Headless example runs

The examples run without a display and can take screenshots:

SDL_VIDEODRIVER=dummy ZIGUI_SCREENSHOT=out.png ./zig-out/bin/demo
SDL_VIDEODRIVER=dummy ZIGUI_SCRIPT="click 700 22;type lay;key enter" ZIGUI_SCREENSHOT=out.png ./zig-out/bin/demo

Script verbs: move X Y, click X Y, press X Y, type TEXT, key [ctrl+][shift+]NAME. The builder and workbench add verbs such as add WIDGET and select N (see runCommand in their sources). Script commands run one per frame, separated by ;.

Environment variables

VariableEffect
ZIGUI_FONT, ZIGUI_MONO_FONTFont file paths.
ZIGUI_SCREENSHOT=file.pngWrite the final frame and exit.
ZIGUI_SCRIPTScripted input (above).
ZIGUI_TRACE=1Examples print damage rectangles per frame and (builder) every input event.
ZIGUI_NOPRESENT=1Render without presenting, to measure rendering cost without the vsync wait.

Build options

  • -Dui_checks=true|false: the shadow checker that warns when you change a prop without marking it dirty. On in Debug and ReleaseSafe, off otherwise. -Dui_strict=true makes it panic.
  • -Dexample_optimize=debug|safe|fast|small: optimization for the examples (default safe).

Performance

ui.stats keeps recent per-frame timings (update, layout, build, submit, handlers); the builder and demo print them in headless runs. Software rendering in Debug is an order of magnitude slower than ReleaseSafe: judge responsiveness in an optimized build.
